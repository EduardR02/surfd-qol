# Surfd QoL

Local Chrome extension for https://surfd.net/. No bundled game code, telemetry, automatic steering or physics changes. Optional native-input nullbinds are off by default.

## Install

The ready-to-load extension is in `dist/`.

1. Open `chrome://extensions` in your normal Chrome profile.
2. Enable **Developer mode**, choose **Load unpacked**, and select `C:\Users\Eduard\vibe-coded\surfd-qol\dist`.
3. Visit or reload Surfd. Initial connection reloads the tab once, so install between runs.
4. Open **QoL → Settings** in the game menu. Settings save automatically in this browser/site profile.

Leave this project folder in place. The unpacked extension loads on subsequent visits and browser restarts. After editing source, run `bun run build`, reload the extension on `chrome://extensions`, then reload Surfd. Chrome 118+ required.

This folder is a local Git repository on branch **main**. Source, tests, extension inputs and documentation are tracked; `dist/` is generated with `bun run build`. `.gitignore` excludes builds, dependencies, coverage, local environment files/browser profiles, packaged extensions, signing keys and editor/OS scratch files. `.gitattributes` keeps tracked text LF-normalized. No remote repository or upload is configured.

## Features

- **Compact centered HUD:** rose speed numerals stay on the viewport centerline, independently of the smaller timer and temporary splits. Movement values sit above their small centered Air/Surf and Board labels. No in-run cards or borders; a restrained two-pixel shadow preserves contrast without an outline or broad glow. Purple-free Rosé Pine accents: rose, foam, gold and love. All four colors are editable under **Style → HUD palette**, with a colors-only reset that preserves layout, thresholds, bindings and reference choices. Vertical position, scale and opacity remain adjustable. The run HUD hides in menus, settings, map selectors, loading screens and blocking modal dialogs, not informational votes, scoreboards or nonmodal notices. Replays and spectating remain eligible without pointer lock. QoL settings remain accessible in menus; disabling the custom HUD restores complete native telemetry.
- **Settings menu:** four sections—**Display**, **Feedback**, **Style**, **Controls**—with readable labels, aligned controls and optional technical details. Feedback legends, fixed cutoffs and sync thresholds show actual live palette swatches with semantic labels, not fixed color names. Palette fields are named by purpose. Fixed thresholds are inside **Feedback → Fixed targets & cutoffs**, separate from PB/WR comparisons. Crouch-jump details stay within their own group above Nullbinds. Arrow keys, Home and End navigate the section tabs. On small screens only the section body scrolls; navigation and Close stay visible. Settings save automatically.
- **Counter cadence:** **Display → Counter refresh** independently configures speed and timer caps, default **60 / 30 FPS**. Integer values from **1–1000** save locally; actual updates are limited by the screen’s animation-frame rate. Either counter can be faster than the other, and changing caps takes effect without a stale-counter pause. No averaging or precision changes. The fast counter path reads local Session scalars or the direct spectator view without deep-cloning the game's full snapshot. It stays separate from the **67 ms** coaching/reference refresh; the game’s frame rate and physics remain unchanged. Menu observers ignore unrelated descendant-class changes. Hidden HUDs stop requesting live frames; showing the HUD immediately refreshes both counters.
- **Independent movement visibility:** **Display → Movement feedback** has separate **Board**, **Air** and **Surf** switches, all on by default. For Board-only, leave Board on and turn Air/Surf off. A sole metric centers; all three off hides the feedback row without hiding speed/time. Air/Surf still share one compact slot: held mode shows the newest enabled completion, with Surf winning equal ticks. Air-only ignores Surf; Surf-only retains Surf when newer Air completes. An unavailable enabled result shows a dash rather than borrowing a disabled type. Live mode maps Air to free-air Strafe, Surf to ramp Input, and Board to Board/Clip; outside the enabled shared type’s movement context it shows a dash. Hidden Board/Surf preferences release unused reference consumers while other enabled metrics/checkpoints keep theirs. Enabled references still prefetch before their first result; core measurement tracking continues while values are hidden.
- **Held Board entry (default):** full-3D collision speed removed at the first accepted contact, plus genuine brief recontacts inside a fixed **90 ms** entry window. Continuous turns never accumulate into Board or erase its result. Connected surfable collision faces keep BSP seams and curved facets together, including overlapping imported facets—not just equal brush IDs. Short skips on a known surface retain one visit for up to **250 ms** of clear air; unknown geometry uses a conservative **45 ms** grace and matching-normal recontacts. The entry window never renews. Ground, a confirmed departure or another known surface ends the visit. Ambiguous new entries show a dash; later ambiguous contacts preserve the accepted entry. Gravity and horizontal/vertical conversion are excluded, but necessary route contacts can still clip speed.
- **Held after-ramp Surf:** once a ramp visit ends, enabled **Surf** replaces Air in the shared slot, without a third counter. It displays `actualExitSpeed − sqrt(entrySpeed² + 2 × nativeGravity × (entryHeight − exitHeight))`, using full-3D speed. Entry is sampled before the first contact tick, including the initial Board; exit is sampled after the last contact tick. Complete native tick endpoints keep height and both gravity half-steps in the same time frame. The first entry survives brief same-ramp recontacts, so the net result spans those skips too. Positive means net gain, negative means net loss after height conversion. Gains offset losses across the entire visit, rather than accumulating only downward steps. At least **50 ms** of actual contact is required. The result is calculated once at confirmed departure and stays unchanged during subsequent flight. Ambiguous contacts, missing/invalid endpoints or gravity, or a negative gravity-only expected squared speed produce a dash, never a clamped fake baseline. Board is a separate entry clip and must not be added. This is net outcome against gravity-only conversion, not avoidable loss or an optimal-route score—even a KSF route can have substantial negative values. Disable **Display → Movement feedback → Surf** to keep Air displayed instead.
- **Held Air:** the last completed free-air section’s actual input braking plus missed positive local gain. **Feedback → Air analysis → Air value** selects **Air braking**, **Missed strafe gain** or **Both combined** (default), with both components retained in the tooltip. Air braking is speed removed by your input; tight turns can require it, so compare the same turn rather than treating it as an error count. Missed strafe gain is extra speed a better local strafe could have added during input; taking every gain can lengthen the route. The selection updates its short inline explanation. At least **50 ms** of supported input is required; coasting/no-input and contact ticks are excluded. Short skips returning to the same ongoing ramp visit do not publish a misleading separate Air section. When both types are enabled, Surf remains visible through the following flight; a completed genuine Air section replaces it at the next landing/board. Neither is a cumulative route-optimal or WR-loss score.
- **Live feedback (optional, off by default):** enable under **QoL → Feedback** when watching a replay or examining technique. The short explanation contrasts continuously updating feedback with the default held results. **Live strafe window** controls how much recent movement enters live **Strafe / Input**, from **0.05–0.50 s**, default **0.20 s**. It is disabled while Live feedback is off and does not change held Air/Board/Surf results. **Input** on a ramp compares feasible alternatives with the same holding pressure, using native float32 acceleration and plane-tangent speed. The same-pressure solver runs only while Live feedback is enabled, not for held Surf/Board or reference replay reconstruction. Held Air still computes its required free-air comparison. Collision **Clip** covers the last **0.50 simulated seconds** of continuing contact, not a growing whole-ramp counter; **Contact** marks ambiguous geometry. Live collision events expire after at most 1.6 s. Unsupported contacts show a dash. Neither live mode nor held Air is a cumulative WR-loss score: compare actual time/speed at checkpoints. Optional **Analysis details** presents a short term-by-term guide rather than a wall of paragraphs. Saved opt-in choices remain saved.
- **Glanceable colors:** **Feedback → Color comparisons** independently selects fixed, PB or WR for Board, Surf and Start. Surf defaults to selected WR. PB/WR Board and Surf are **teal at or better**, **gold up to 2 u/s worse**, and **red beyond**; edit **Near-reference margin** to change the gold band, or set zero to remove it. Differences compare at 0.1 u/s precision to avoid invisible float-noise penalties. The displayed value stays raw, and signed reference gains remain signed. Fixed modes and Air use separate teal/gold cutoffs, default **5 / 20 u/s**, with red at or above the gold cutoff. Missing, incompatible or unmatched references are grey—never silently replaced with fixed colors or another WR. WR follows **Display → World record source**. Matching requires known connected surface, checkpoint and per-surface visit with trustworthy history, not a global ramp number. Unrelated earlier known detours do not break later matches. PB uses the official pre-run replay, frozen during the run. These are measured comparisons, not proof of an avoidable mistake. Native sync stays teal at **95%+**, gold at **85%+**, otherwise red. Ranked is implicit; practice shows **PRACTICE**.
- **Start flash:** a small **Start** heading above actual exit **Speed** and signed platform **Height**, with no cap fraction, source label or HIGH/LOW text. Disappears after 1.8 seconds. The tooltip retains the native cap and speed deficit (normally 350 u/s airborne, 325 grounded), reference source, and unrestricted-start status. Height uses a native solid-world foot-box trace just inside the exit edge, or the most recent measured ground support in that start zone for an airborne exit beyond the ledge. Crouching does not lower the reference by the crouch hull height. Positive means above the platform; negative means below the ledge. Missing support shows a dash. This is a platform reference, not proof of a globally lowest reachable route.
- **Start grading:** **Feedback → Start** selects fixed targets, official pre-run PB, or selected KSF/leaderboard WR. PB/WR uses **teal at or better, red worse**, independently for higher exit speed and lower platform height, compared at 0.1-unit precision. It does not use the Board/Surf gold margin. Missing/loading references remain grey; no fallback is substituted. Fixed targets are editable under **Fixed targets & cutoffs**: height below **7.5 / 15 u**, speed deficit below **10 / 17.5 u/s** by default. Below the first cutoff is teal, below the second gold, otherwise red. Displayed numbers always remain actual exit speed and platform height. Start, Board, Surf and checkpoints share native reconstruction when their source agrees. A cold reference must finish reconstructing before it can color the flash. The Style preview is explicitly an illustrative palette example: its two readings demonstrate configured better/loss colors even when PB/WR is selected, without pretending to be a measured comparison.
- **Checkpoint time and speed:** actual split time and speed remain together; each **PB** and **WR** label appears once beside large time and speed deltas. Choose PB, WR or both, and independently select **KSF record route** (default, “Watch the record route”) or **Surfd leaderboard #1** as WR. Each source uses one complete replay, never per-checkpoint maxima or silent fallback to the other source. KSF uses the imported route's native config; leaderboard speeds must reconstruct exactly to its run identity, timing, splits and current map/config. Source switching cancels stale WR work without disturbing PB reconstruction. Exact speeds from future valid local PBs are saved; practice/invalid runs cannot become references, and the pre-run PB is frozen so a new PB does not compare against itself.
- **Crouch-jump:** Space by default, configurable. Holds native jump while the effective jump key is held, but emits crouch for only the first physics tick of each effective press. Releasing/repressing between samples starts a fresh tap; merely holding the key does not repeat crouch. Other manual crouch keys and the game's own crouch transitions remain native. No synthetic keyboard events or wall-clock timers. Native bindings remain unchanged on disk. Keys assigned to another action are rejected rather than stealing that action. Disabling restores normal jump/crouch input; optional nullbinds remain independent.
  Native engine verification confirmed the first crouch tick raises `duckFraction` before jump processing. The jump checks `ducked || duckFraction > 0`, so a full crouched hull is not required: the tap produced **+6 u/s vertical velocity** versus a normal jump, the same initial impulse as held crouch. The following command releases crouch while keeping jump held.
- **Nullbinds:** independent **A / D** and **W / Space** switches under **Controls**, both off by default. The newest physical press suppresses the other held key in that pair. Releasing the winner resumes the older still-held key; keyboard auto-repeat cannot steal priority. W / Space cuts forward input while Space wins, not existing forward momentum, and suppresses jump while W wins. Resuming Space is a fresh effective jump press, including a one-tick crouch tap when crouch-jump is enabled. Filtering happens in native command construction: both sampled/recorded commands and native key previews see the same winning movement/jump input. Previews do not consume wheel state or crouch-tap edges. Physical key state/order, other input, native bindings on disk and simulation physics remain unchanged. Existing replays are not rewritten; new recordings contain the effective native commands. Priority resets on native input clear, lost focus or pointer unlock. A replaced native binding map immediately disables the old crouch pulse until the controller reconciles it; another key’s jump cannot be misattributed to the old crouch key. Cleanup restores its owned map on the original input object only, never overwriting or clearing a replacement input.
- **Replay and spectator views:** native command replays retain exact movement coaching. A separate **Hull: crouched / standing** row inside the native bottom-right key display reports the actual replay hull state, independently of the Crouch key highlight. Online spectating uses the watched player's transmitted speed/time and available checkpoint progress, never the paused local player's state. Network poses do not expose a full physics session or exact checkpoint samples, so exact coaching and checkpoint time/speed comparisons are unavailable there and show dashes.

## Permission and failure behaviour

Chrome's broad **debugger** permission produces Chrome's own “started debugging this browser” banner. It is not a game popup or optional QoL notification. The current loader uses the [Chrome Debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger) to intercept Surfd's main module and expose its private simulation objects. The implementation restricts attachment to Surfd's root game page and intercepts only `assets/game-*.js`. It appends an adapter and observes existing movement methods without changing their calculations or return values. Maps, assets and physics are not replaced. Cached/304 responses work without disabling the asset cache.

Both the far-right **×** and **Cancel** terminate the debugging connection; × is not a hide-only action. Chrome’s [global warning close handler](https://github.com/chromium/chromium/blob/main/chrome/browser/devtools/global_confirm_info_bar.cc) closes the warning, whose [destruction callbacks](https://github.com/chromium/chromium/blob/main/chrome/browser/extensions/api/debugger/extension_dev_tools_infobar_delegate.cc) reach [debugger cancellation](https://github.com/chromium/chromium/blob/main/chrome/browser/extensions/api/debugger/debugger_api.cc). Opening DevTools can also detach it. This stops the module loader, not code already injected into the current page: the native input-sampler hook, including crouch-jump and nullbinds, stays installed after successful initialization. On detach the extension asks the current page whether its observer is healthy: initialized page features keep the green **ON** badge; incomplete or unavailable setup gets red **!**. The toolbar tooltip distinguishes an inactive loader from failed page features. Dismissing before injection finishes can interrupt setup. A reload needs a new debugger attachment and can show the banner again; use the extension toolbar button between runs to reconnect/reload. The current loader cannot suppress Chrome's security UI, but that UI does not need to remain open for an already-installed input hook. If Surfd changes its private layout, the adapter fails open rather than guessing.

Replay references are limited to 40,000 commands, matching the site's checkpoint worker. Unavailable, incompatible or failed replays show a dash or neutral Board/Start/Surf colors. Local checkpoint PB data/settings live in Surfd localStorage; clearing site data removes them. **Checkpoint, Board, Surf and Start share one identity-keyed replay store:** one download and native simulation for the same selected replay, including simultaneous PB/WR consumers of the same official run. Distinct PB/WR replays require distinct passes. The completed in-memory cache holds at most **12 routes**, including KSF checkpoint data. Unchanged pending work survives run starts/restarts; source/session/map/config changes prevent stale publication. Hidden consumers release pending work; another interested consumer keeps the same job alive. Completed caches remain reusable. Work yields between **32-command slices**, with prototype observers restored before every await and on cancellation/errors. Reference-only observation retains cheap airborne/grounded branch tracking, but skips acceleration optimum analysis and pressure solving. It collects Surf endpoints in the same pass, and copies Board only on mutation and Surf only when a completed visit changes. Live Air optimum calculation is deferred until free-air classification; held ramp ticks do not compute and discard it. Observer scratch payloads/vectors are reused, and contacts use an array offset rather than a slice. Finish/PB bookkeeping stays active behind menus and receives a synchronous native finish notification.

Checkpoint and feedback validation remain independent views of the shared pass. Replay-only timer flags do not invalidate a recorded reference; official time/split identity and compatible map/config must still agree. Imported KSF formats may differ historically. Board/Start/Surf compare all movement-config fields, excluding only the descriptive `version` label and `unrestrictedStart` start-cap flag; native ramp movement uses neither. Each replay still reconstructs under its own original native config and format. This permits Boreas KSF comparisons against current capped runs without accepting actual movement-setting differences. Entry speed and route differences remain part of the comparison, not proof of avoidable loss. Checkpoint KSF reconstruction deliberately accepts its own replay config, even when feedback is incompatible. Geometry indexes are cached per map/ground threshold. Connected collision geometry is not a mapper-authored logical ramp ID; unsupported geometry stays unmatched. Air has no PB/WR replay comparison: its braking and missed-gain values come from the current run’s local acceleration observations.

Server replay acceptance is not an assurance about leaderboard policy. See [Surfd's terms](https://surfd.net/terms.html); this extension does not submit runs or bypass validation.
